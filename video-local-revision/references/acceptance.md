# 验收与模型更换

## 当前任务的验收

依据用户要求选择检查，避免为普通修改追加整套流程。

| 检查层 | 可观察的依据 | 不能单凭它得出的结论 |
| --- | --- | --- |
| 技术规格 | 分辨率、帧率元数据、实际解码帧数、时长、音轨存在性、完整解码结果 | 视觉合格、声音内容完全相同、VFR 的每帧时间完全相同 |
| 单帧贴合 | 原片与成片的对应帧，必要时用[原尺寸局部对照](tools.md#局部对照)，检查结构、边界、遮挡和材质 | 整段没有漂移或闪烁 |
| 时间连续性 | 原速播放目标帧段，查看触发前后、最难帧和最后状态 | 其他未查看镜头也已验证 |
| 修改范围 | 比较未编辑区域及时间段；容许合理的编码误差和已授权的间接影响 | 所有像素不同都是越界，或者相似度高就一定改对了 |
| 可编辑交付 | 工程与依赖能打开，按所需范围进行重现检查 | 只交一个模型文件就能复现成片 |

若直接复制音轨，可以另行比较音频数据或解码后的音频；若重新编码，检查时长、同步及实际声音。脚本只比较元数据时应明确记录。哈希相同适合证明文件复制完整，不能评价艺术质量。

视觉检查由实际有查看能力的执行者完成。困难、持续失败或模型更换后效果不明时，可提交对照给用户或独立审查者；不设置每次任务必经的人工作业审批。判断不明就保留“未验证”，不要强行填 PASS。

## 用于首次启用或模型更换的样例

以下是测试请求及观察重点，供有界试用。可选择当前任务相关的一项；不要求每次制作都执行。

1. **灯光时序**：“保持上方灯关闭，在指定声音处让竖灯高亮，再降至参考亮度并保持到结尾。”观察事件对齐、过渡、灯壳跟踪和最终状态；不能只比较峰值帧。
2. **部件替换**：“用多角度参考修复后视镜，保持原镜头焦外。”观察结构、安装根部、遮挡和软化边缘；模型应区分错误的三维朝向与跟踪问题。
3. **屏幕替换**：选当前相关的一种。整屏换画观察比例取舍、边缘与遮挡；局部换字可用“只改指定帧段红框里的两行数字，保留扫过的反光、折线与刻度”，观察最强反光下是否滑动、未改界面是否变色，以及两端接点是否跳变。用实际成片和原片的对应帧检查。
4. **新素材迁移**：换一段没有用于编写本能力包的镜头，改变分辨率、光照或视角变化。观察是否重新估计参数，是否错误套用奥迪案例的 4K、25 fps、像素偏移或旧时间点。
5. **复杂条件**：选有遮挡、强反光或屏幕曲率的短片。观察是否识别默认方法的边界、提出必要处理，并用可观察结果验证。不要把“步骤做完”记成成功。
6. **范围与纠正**：“先判断灯为什么飘，暂时不要改视频”；随后给出只改变结尾灯态的新需求。观察是否先诊断、只覆盖冲突要求、保留其他有效成果。

比较模型或新方法时使用相同输入、目标和可接受的成本条件，记录实际质量、返工次数、耗时与未解决问题。至少包含一段新素材，避免只记住案例参数。对照短片可帮助理解要求，不能作为弱模型自行证明能力的唯一题目。

可把[手机屏幕练习](../examples/phone-practice/任务.md)直接交给待测模型。看实际导出中的两行正负号、小数、百分号及位置，把最斜视、反光最强和首尾帧与源片并排看，再以原速检查连续性。对照折线、底部刻度和原声。模型更换时用同一题记录成片质量、返工次数和耗时，遇到重复卡点再补该环节的制作方法。

## 判定记录

用短句记录即可：检查对象；所看帧段；技术检查结果；观察到的视觉问题；尚未检查项；最终文件位置。技术、视觉与可复现性分别记录，不用单个总分掩盖缺项。
