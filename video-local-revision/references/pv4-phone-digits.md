# PV4：反光扫过时替换手机屏幕上的数字

**任务**：只换参考框内的两行数字，保留原界面的折线、底部时间刻度、原声和屏幕反光。返修集中在 `00:00:01:00` 到 `00:00:02:16`，以原片的位置和运动为准，接回已确认的后续画面。该片 3840×2160、25 fps，共 110 帧（4.4 秒）。返修复核区间按零基索引为第 25–66 帧，含首尾。

| 当时需要解决的问题 | 适用的处理 |
| --- | --- |
| 手机翻向镜头、反光经过时，数字相对界面滑动 | 先跟踪手机的大体投影，再在拉正的屏幕上用摄像头开孔和未改的折线折点等固定特征校准。清晰帧提供绝对位置，反光下匹配不稳的帧由可信的局部测量及邻帧运动约束。 |
| 旧字要清干净，同时保留扫过字面的反光 | 用两行周围同一帧的干净玻璃带恢复字下底片；按行及横向位置估计原笔画相对底色的反差，使反光可先经过一部分笔画，再扫过其余位置。按原片运动和焦点匹配笔画模糊。 |
| 到区间末尾接回后段时，字的位置或亮度跳一下 | 检查接点前后源片对应帧；对齐字形位置后，让一套字形逐步衔接后段的色调、反差和清晰度，避免两套字叠出重影。 |
| 需要证明没动折线和刻度 | 在实际解码的母版中对照这些区域；用相同的时间位置、裁切及色彩解释复查预览。 |

历史交付记录：输出为 4K ProRes 母版和 1080p 预览。对相关区间解码后，单独定位原字与合成文字的可辨认笔画；在匹配置信度足够的相邻帧对中，两者相对位置的帧间变化中位数从约 1.1 像素降至约 0.3 像素。它衡量的是该区间的残余抖动，不代表所有帧绝对位置误差都小于 0.3 像素。案例记录不附工程或新视频，也不替代原速视觉检查。

该项目的母版额外核对了不受修订影响的视频包、压缩切片及原音轨数据。仅当交付明确要求保留编码数据、素材格式兼容且能验证实际输出时，才采用类似策略；常规工作在正确的色彩设置下正常导出，并核对未修改区域即可。
